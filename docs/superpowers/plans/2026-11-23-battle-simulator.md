# 전투 시뮬레이터 계획 (Windows PC에서 진행)

## Context
서버 그룹 577-584 전략용으로 BGB(블랙골드), 서버 클래시(수도전), 전투력 성장, 타워 공략을 시뮬레이션하고 싶다.
사용자 결정: **게임 데이터 기반 정밀 재현**, 첫 모드는 **BGB**. 상대 선수 명단은 이전 대결 기록에서 이름만 참고하고
전투력은 항상 최신값으로 받는다. 서버 클래시에서는 "수도의 강자를 점령하려면 얼마나 타격해야 하나, 랠리에 누가 들어가면
예상 피해가 얼마인가"를, 전투력 시뮬은 성장 예측과 "타워를 무너뜨리는 데 필요한 피해, 나/그룹의 집중공격 성공 가능성"을 원한다.

문제: 저장소에 **전투 계산식이 없다.** 전투 리포트 본문(메일 타입 72 PvP·타워, 157 수도전)은 base64 protobuf로 일부만
해독됐고(`docs/runbooks/capture-sweep.md` 150행), 클라이언트 datatable 473개 덤프는 Windows PC에만 있다
(`C:/DW_data/gamedata`, `dw-collector game-dump`). 정밀 재현 가능 여부는 데이터를 열어봐야 안다. 그래서 0단계가 관문이다.

## 0단계 — 공식 조사 (Windows PC, 코드 변경 없음, 산출물은 `docs/runbooks/combat-model.md`)
1. 덤프에서 전투 관련 테이블 목록화: 영웅·스킬·병종(공격/방어/HP)·상성·타워/건물 HP·버프(35000/40001대 ID)·연구·장비·펫.
   도구: 기존 `game-dump --dry-run`, `game-catalog`, 설정 > 게임 데이터 테이블 브라우저(0343 적용 후).
2. 서버가 계산하는 값(피해 공식, 라운드 진행)이 데이터에 있는지 판정. 클라이언트 Lua/번들에 전투 로직이 있는지
   (UnityPy, 기존 `lupa` 경로) 확인.
3. 저널에 쌓인 전투 리포트(72/157)를 해독 확장: 적 병력, 잔여 병력, 라운드별 HP, 버프 표(#5.8). 스카우트 리포트(타입 8)로
   상대 스탯 입력 형태 확인.
4. **검증 세트**: 입력(양측 병력·영웅·버프)과 결과(잔여 병력·피해)가 모두 있는 실제 전투 N건을 뽑는다. 이후 모든 모델은
   이 세트에 맞는지로 판정한다.
5. 판정: (A) 공식이 데이터에 있음 → 정밀 엔진, (B) 일부만 있음 → 데이터 + 리포트로 계수를 맞춘 하이브리드,
   (C) 없음 → 근사 모델만 가능하다고 명시. 결과를 사용자에게 보고하고 이후 단계 범위를 확정한다.

## 1단계 — 전투 엔진 (순수 TS, UI 없음)
- 위치: `apps/dashboard/src/features/battleSim/` (새 폴더, 필요해질 때 생성). `Observation` 원칙처럼 DB·네트워크 무관한 순수 함수.
- 입력 타입: 병력/영웅/버프 스냅샷 → 출력: 잔여 병력, 피해량, 승패. 0단계 검증 세트를 픽스처로 넣어 회귀 테스트(정확도를 숫자로 기록).
- 공식이 확정 안 된 부분은 계수를 파일 한 곳에 모으고 "추정"으로 표시. 스코어링처럼 버전을 붙여 덮어쓰지 않는다.
- 데이터는 가능하면 DB(`game_*` 테이블)에서 읽는다. 재사용: `features/planner/data.ts`, `plan.ts`(전투력 계산), `lib/serverClash.ts`.

## 2단계 — 전투력 성장 예측
- 플래너(`features/planner`)의 `plan.ts`/`recommend.ts`를 확장: 투자 계획 → 전투력 시계열 예측.
- 엔진이 있으면 "전투력"이 아니라 실제 피해량 기준 이득도 표시.

## 3단계 — BGB 배치 평가
- 기존 `BgbPlanPanel.tsx`, `bgbPlan.ts`, `battlefield.ts`에 평가 패널 추가.
- 상대 명단: 지난 대결의 선수 이름 목록만 가져오고, 전투력·상태는 `players`/`alliance_roster_latest` 등 **현재값**으로 조회.
  (명단에 없는 이름이면 "미확인"으로 표시.) 사용자가 직접 추가/제외 가능.
- 출력: 목표지점별 우세/열세, 배치 대안 비교(간단한 탐색), 불확실성 범위.

## 4단계 — 서버 클래시(수도전) + 타워 집중공격
- `lib/serverClash.ts`(`server_clash_compare`)의 양 서버 플레이어 데이터를 입력으로 재사용(관리자 화면 `ServerClashSetting.tsx` 옆 또는 별도 탭).
- 수도: 상대 강자 지정 → 필요한 총 피해, 랠리 구성(우리 멤버 선택) → 예상 피해와 점령 가능성.
- 타워: 타워 HP(리포트에서 읽힘) 대비 필요한 피해, 개인/그룹 집중공격 시 성공 확률(몬테카를로는 엔진이 확률적일 때만).
- 수도/타워 리포트 해독 정도에 따라 이 단계 정밀도가 정해진다.

## 규칙 준수
- 새 DB 테이블은 정말 필요할 때만(스키마 규약, `new-migration` 스킬; 번호는 push 시점의 `origin/main` 기준, RLS면 pgTAP 음성 테스트).
- 새 전투 리포트 파서는 `promote-command` 절차(정제 픽스처, 테스트 4종).
- 스코어링 버전 고정 금지, 게임 공식 변경에 대비해 계수는 한곳에.
- 작업은 Windows PC 체크아웃에서: `C:\darkwar-platform`, 브랜치 `main` 확인, `uv run --no-sync` 사용.

## 검증
- 0단계: 검증 세트 N건과 목록·판정 문서가 산출물. 사람이 읽고 A/B/C 판정에 동의.
- 1단계: `pnpm test`(엔진 단위 테스트, 검증 세트 정확도 보고), 전체 게이트
  `pnpm check && pnpm typecheck && pnpm test && pnpm build`.
- 2~4단계: 위 게이트 + `run-dashboard` 스킬로 화면 확인(실데이터 미확인 항목은 handover에 명시).
- 각 단계는 별도 PR. 시뮬 결과 화면에는 "추정치"와 검증 세트 정확도를 표시.

## 열린 질문(0단계 후 확정)
- 정밀 재현이 불가(C)로 판정되면 근사 모델로 갈지, 해독 범위를 늘릴지.
- 수도전·타워 리포트가 얼마나 해독되는지.
