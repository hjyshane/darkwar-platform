# DB 성능: 2026-08에 배운 것 (요약)

2026-08-05~09의 성능 사건 연쇄(0088~0154)를 한 장으로 줄였다. 근거와 측정은 `docs/log/2026-08.md`의 해당 항목에 있고, 이 문서는 **다음에 같은 병을 만났을 때 먼저 볼 것**만 적는다. 숫자를 바꾸기 전에 원문을 읽는다.

## 원칙

1. **프로덕션 `EXPLAIN`을 받기 전에는 고쳤다고 말하지 않는다.** 0102→0103→0104가 프로덕션에서 연달아 타임아웃났고(0103은 프론트를 8쿼리로 되돌리는 것으로 끝남, PR #181), 프로덕션 EXPLAIN(0105)을 받고서야 끝났다. 로컬 재현은 통계 모양까지 맞춰야 의미가 있다(프로덕션과 같은 형태의 시드 + `analyze`).
2. **RLS 아래서의 실행은 superuser와 다른 계획이다.** 같은 select가 superuser 2 ms, member 세션 137 ms였다(0100). `member_read`가 부르는 `current_app_role()`은 SECURITY DEFINER + `SET search_path`라 플래너가 인라인도 추정도 못 하고, 행 추정이 1로 무너져 nested loop가 된다. 안쪽 서브쿼리가 멤버마다 재실행된다.
3. **추정을 고치려 하지 말고 울타리를 친다.** 해당 읽기를 `as materialized`로 감싸 각 스캔이 정확히 한 번이게 한다(137 → 9 ms). 계획 텍스트에 핀을 박는 테스트(`60_movement_plan_test`, `59`)로 회귀를 막는다.
4. **읽기 시점 계산은 걷어낸다.** 큰 테이블을 매번 훑는 보드는 작은 사전 계산 테이블이 묻게 한다(0149: 1.76M행 → 82행, 0154: 시즌 보드, 0106: precompute 착지). 사전 계산이 어긋나면 안 되므로 **무엇이 쓰는가**를 먼저 확인한다.
5. **`eq`와 `in`이 스무 배 차이 났다**(0150·0151). 필터 모양이 계획을 바꾼다 — 화면이 쓰는 정확한 쿼리 모양으로 잰다.
6. **창 함수는 매번 전체를 정렬한다**(0153: 88,079행). 읽을 때마다 도는 곳에 두지 않는다.
7. **서비스를 잠그는 마이그레이션이 있다**(0152 — 0150이 서비스를 잠갔다). 큰 테이블을 건드리는 마이그레이션은 잠금 범위를 먼저 본다.
8. **끝났다고 선언한 곳은 더 파지 않는다.** Trends 탭과 멤버 상세는 ~1초이고 사용자가 "아주 만족"이라고 명시했다. 남은 1초는 RTT × 얕은 워터폴이다. 필요해지면 0106/0107 패턴을 그대로 쓴다.
9. **`select *` 뷰의 별은 만들 때 한 번만 펼쳐진다** → [traps.md](traps.md).
