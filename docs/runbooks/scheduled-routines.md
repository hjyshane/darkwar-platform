# 예약 루틴 (에이전트 점검)

사람이 잊는 점검을 주기 작업으로 돌린다. **읽기 전용**이고, 보고만 한다 — 수정·커밋·푸시·머지·`db push`는 하지 않는다. 루틴 본문은 `~/.claude/scheduled-tasks/<id>/SKILL.md`에 있고 Claude 데스크톱 앱의 "Scheduled"에서 고친다(이 저장소에는 없다).

## `dw-weekly-repo-health` — 매주 월요일 09:07 (로컬 시간)

| 점검 | 근거 |
|---|---|
| main의 최근 7일 CI 실패/취소, 실패한 잡 이름 | CLAUDE.md: "머지 전에 db 잡을 읽어라" |
| supabase/를 건드린 머지인데 `db` 잡이 skipped인 것 | 위와 같음 — 못 돈 검사가 초록으로 보이는 경우 |

| 열린 PR 중 실패한 체크 / 7일 이상 방치 | — |

출력은 한국어 30줄 이내, "조치 필요"가 맨 위. 모르는 것은 "모름"이라고 쓰게 했다.

### 알아 둘 것

- **앱이 켜져 있을 때만 돈다.** 꺼져 있으면 다음 실행 때 한 번 돈다.
- **자동 모드로 저장됐다.** 앱에서 실행 방식을 바꿀 수 있다. 자동 모드를 쓸 수 없으면 도구 승인을 물으며 멈출 수 있다 — 첫 주 결과가 안 오면 이것부터 본다.
- **아직 한 번도 돌려 보지 않았다.** 2026-11-12에 "지금 실행"을 시도했으나 자동 모드 분류기가 거부했다. 첫 정기 실행 결과를 보고 프롬프트를 고친다(`gh`/`git` 읽기 명령이 승인 없이 되는지가 핵심).
- 질의 자체는 같은 날 손으로 확인했다: `gh run list`, `gh run view --json jobs`, `git ls-tree origin/main supabase/migrations/`, `gh pr list --json statusCheckRollup` 모두 동작.

## 아직 안 만든 것 (데이터가 있는 머신이 필요)

- **미인식 커맨드 / `raw` 새 키 주간 요약**: 데이터는 Windows 수집기의 로컬 SQLite와 Supabase에 있고, 이 맥에는 실데이터가 없다. 서비스 키를 예약 작업에 넣지 않는다. 만든다면 Windows에서 `dw-collector command-catalog`/`survey` 출력을 읽는 방식이어야 한다.
- **PR 자동 수정**: 이미 앱의 Auto-fix가 한다. 루틴으로 중복하지 않는다.
